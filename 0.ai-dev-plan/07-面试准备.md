# 面试准备

> 时间：第 7 个月起（2027.5），每周一、周三晚上
> 内容：计算机基础、大模型/RAG/Agent 面试题、系统设计、项目讲述、简历、常见的"非技术"问题

---

## 一、AI 应用开发岗的面试流程

| 轮次 | 一般考什么 |
|---|---|
| 简历筛选 | 项目经历、GitHub、技术栈是否匹配 |
| 一面 | 计算机基础、Python、算法题、项目概述 |
| 二面 | **项目深挖**、大模型/RAG/Agent 原理、简单的系统设计 |
| 三面 / 主管面 | 综合能力、学习能力、职业规划 |
| HR 面 | 离职原因、薪资期望、稳定性 |

创业公司流程通常更短，可能两轮就结束，但项目深挖会更狠。

## 二、计算机基础（非科班一定会被问）

资料推荐：小林 coding（xiaolincoding.com），图解风格，适合快速掌握。

### 计算机网络

- [ ] 在浏览器输入一个网址后，到页面显示出来，中间发生了什么？（最经典的一道题）
- [ ] TCP 和 UDP 的区别
- [ ] TCP 三次握手、四次挥手，为什么是三次和四次
- [ ] HTTP 和 HTTPS 的区别；HTTPS 加密的大致过程
- [ ] 常见 HTTP 状态码的含义
- [ ] Cookie、Session、JWT 的区别（结合你的待办项目来讲）
- [ ] SSE 和 WebSocket 的区别（结合你的流式输出来讲）

### 操作系统

- [ ] 进程、线程、协程的区别
- [ ] 死锁是什么，产生的条件，怎么避免
- [ ] 虚拟内存的概念
- [ ] 进程间有哪些通信方式

### 数据库（MySQL）

- [ ] 索引是什么，为什么用 B+ 树
- [ ] 什么情况下索引会失效
- [ ] 事务的 ACID 特性
- [ ] 四种隔离级别，以及脏读、不可重复读、幻读
- [ ] 怎么排查和优化慢查询（EXPLAIN）

### Redis

- [ ] 常用的数据类型和各自的使用场景
- [ ] 为什么 Redis 快
- [ ] 缓存穿透、缓存击穿、缓存雪崩，以及各自的解决办法
- [ ] 过期删除策略和内存淘汰策略（结合 LRU 那道算法题来讲）

### Python

- [ ] GIL 是什么，对多线程有什么影响
- [ ] 深拷贝和浅拷贝
- [ ] 装饰器的原理，现场手写一个
- [ ] 生成器和迭代器
- [ ] asyncio 的原理：事件循环、协程
- [ ] 什么场景该用多线程、多进程、协程

## 五、系统设计（简化版）

AI 应用岗一般不会考复杂的分布式设计，但可能会问：

1. **设计一个企业内部知识库问答系统，支持 1 万名员工使用。**
   - 要考虑：文档怎么接入和更新、权限控制（员工只能查到有权限的文档）、并发、缓存、成本、怎么评测效果
2. **设计一个智能客服 Agent。**
   - 要考虑：哪些问题让 AI 处理、哪些转给人工；怎么调用订单系统；怎么防止 AI 乱承诺；怎么监控服务质量

**回答框架：** 先问清需求和规模 → 画出整体架构 → 讲核心流程 → 讲关键难点和取舍 → 讲怎么监控和评测。

## 六、怎么讲项目

### 准备两个版本

**1 分钟版本**（开场自我介绍时用）：
> 我做了一个 XX，用来解决 XX 问题。核心技术是 XX。通过 XX 优化，把 XX 指标从 XX 提升到了 XX。

**5 分钟版本**（项目深挖时用），按这个顺序讲：
1. **背景：** 解决什么问题，为什么值得做
2. **架构：** 画图讲整体设计
3. **难点：** 选 2–3 个最有挑战的技术点，讲清楚你是怎么解决的
4. **数据：** 实验记录表、评测结果
5. **反思：** 还有哪些不足，如果重做会怎么改

### 准备好被追问

对项目里的**每一个技术选型**，都要能回答这三个问题：
- 为什么选这个？
- 考虑过哪些替代方案？
- 它有什么缺点？

## 七、简历

### 结构（一页）

```
1. 个人信息：姓名、电话、邮箱、GitHub 链接
2. 技能：Python、FastAPI、MySQL、Redis、Docker、RAG、Agent、LangGraph、MCP……
   （只写你能被深挖的）
3. 项目经历（放在工作经历前面，这是你最大的卖点）
   - 项目二：数据分析 Agent
   - 项目一：技术文档问答助手
4. 工作经历
5. 教育经历（放最后，一行即可）
```

### 项目经历的写法

每个项目 3–5 条，每条尽量带上**数字**：

```
数据分析 Agent | Python, LangGraph, MCP, PostgreSQL, Docker | GitHub 链接 | 演示链接
- 设计并实现基于 ReAct 的数据分析 Agent，支持自然语言查询、SQL 生成、自我修复、沙箱代码执行与图表生成
- 构建 XX 个分析任务的评测集，任务成功率从 XX% 提升到 XX%；对失败案例分类分析并针对性优化
- 将数据库能力封装为 MCP Server；实现只读账户、SQL 白名单、容器沙箱等多层安全机制
- 对比手写循环与 LangGraph 两种实现，在可调试性、断点恢复、人工确认等方面做取舍分析
```

### 过去的工作经历怎么写

**原则：只写你做过、能讲清楚的。** 有参与但不是主导的，就写"参与"或"协助"。被面试官追问后发现夸大了，比经历平淡更伤。

下面是写法参考，括号里的内容按实际情况填写：

```
大模型 Coding 评测 |（公司）|（时间）
- 按评测题目对多个模型配置的 Coding Agent 进行多轮交互测试，对生成的代码产物进行功能验证与打分
- 累计完成（XX）道题目的评测，积累了对 Coding Agent 常见失败模式的一手认知

鸿蒙端侧开发工程师 + 项目 PM |（公司）|（时间）
- 负责（XX 模块）的鸿蒙端侧开发（ArkTS / ArkUI）
- 担任项目 PM，协调（X）人团队，推进（XX）版本按期交付

Android CameraHal 开发实习 |（公司）|（时间）
- 参与 Camera HAL 层问题定位，通过日志与 Trace 分析协助排查（XX 类）问题
```

> ⚠️ 不要在简历或面试中透露前雇主和客户的内部信息，比如未公开的模型名称、内部数据、具体评测内容。

## 八、常见的"非技术"问题

### "你不是计算机专业的，怎么证明你的能力？"
> 用项目说话。"我系统学习了 XX，独立完成了两个项目，GitHub 上可以看到完整的代码和提交记录，项目也部署上线了，可以现场演示。"

### "为什么从之前的工作转到 AI 应用开发？"
> 讲正面的原因，**不要抱怨前雇主**。参考方向："在做评测的过程中，我近距离看到了 Agent 的能力和问题，对怎么把它做好产生了很大兴趣，所以系统学习了后端和 Agent 开发，自己动手做了项目。"

### "你之前的工作是外包，有什么想法？"
> 坦然承认，然后把话题转到你学到了什么、现在能做什么。不要贬低外包，也不用自卑。

### "你的职业规划是什么？"
> "未来 2–3 年在 AI 应用开发方向持续深入，特别是 Agent 的工程化，比如可靠性、评测、安全。"

### "期望薪资是多少？"
> 面试前先在 Boss 直聘上调研同类岗位的薪资范围，给一个区间，不要只给一个数字。

## 九、反问环节（准备 2–3 个）

- 这个岗位日常的主要工作是什么？用到哪些技术？
- 团队现在的 AI 项目处在什么阶段，是已经上线还是在探索？
- 对新人来说，前 3 个月需要达到什么样的状态？

通过反问判断这个岗位是**真的写代码**，还是只用低代码平台配置。

## 十、模拟面试

用 ChatGPT 做模拟面试，提示词见 `08-ChatGPT使用指南.md`。建议：
- 每周至少 1 次，每次 30–45 分钟
