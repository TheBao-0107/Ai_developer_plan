## 准备：选一个 API

推荐 **DeepSeek** 或**阿里云百炼（通义千问）**。原因：便宜、国内访问稳定、**兼容 OpenAI 的接口格式**。兼容意味着学会一套写法，换模型只需要改两行配置。

```python
# 安装：uv add openai python-dotenv
import os
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()  # 从 .env 文件读取 API Key

client = OpenAI(
    api_key=os.environ["DEEPSEEK_API_KEY"],
    base_url="https://api.deepseek.com",  # 换成百炼时改这里
)

resp = client.chat.completions.create(
    model="deepseek-chat",                 # 模型名以官方文档为准
    messages=[
        {"role": "system", "content": "你是一个简洁的助手"},
        {"role": "user", "content": "用一句话解释什么是 API"},
    ],
)
print(resp.choices[0].message.content)
```

> ⚠️ 在平台上**设置消费上限**，API Key 写在 `.env` 里，不要提交到 GitHub。
> ⚠️ 模型名、接口地址会变，**以官方文档为准**。ChatGPT 给的可能已经过时。

## 第 16 周：结构化输出和 Function Calling

| 天 | 内容 |
|---|---|
| 周一 | 结构化输出：JSON 模式；用 Pydantic 校验模型返回的 JSON；校验失败时自动重试 |
| 周三 | Function Calling 原理：用 JSON Schema 描述工具，模型返回要调用的工具名和参数，**由你的代码去执行** |
| 周五 | 多工具调用、一次请求里并行调用多个工具、工具出错时怎么处理 |
| 周末 | **练习：** 给聊天后端加 3 个工具（见检验标准） |

### Function Calling 的循环结构（一定要理解）

```
1. 把 用户消息 + 工具描述 发给模型
2. 模型返回：
   ├─ 普通文本 → 直接回复用户，结束
   └─ 要调用工具（工具名 + 参数）→ 进入第 3 步
3. 你的代码执行这个工具，拿到结果
4. 把 工具结果 追加到消息列表，回到第 1 步
```

**这个循环就是 Agent 的雏形。** 第 6 个月学的 ReAct Agent，本质上就是这个循环加上规划、记忆和错误处理。

## ✅ 第 4 个月检验标准

一个**智能助手后端**（FastAPI），满足：
- [ ] 流式输出接口
- [ ] 支持多个会话，对话历史存在 Redis
- [ ] 至少 3 个工具，模型能自己判断什么时候调用：
  - 查天气（用免费的 Open-Meteo API，不需要注册）
  - 计算器
  - **查我的待办**：调用你第 2–3 个月做的待办清单 API
- [ ] 一个结构化抽取接口：输入一段文字（比如一段招聘 JD），输出 JSON（公司、岗位、薪资、技能要求），用 Pydantic 校验
- [ ] 部署到云服务器

**并且能口头讲清楚：**
1. Function Calling 的完整流程
2. Transformer 大致怎么工作，为什么大模型会有幻觉
3. `temperature` 调高和调低分别有什么效果，各适合什么场景
